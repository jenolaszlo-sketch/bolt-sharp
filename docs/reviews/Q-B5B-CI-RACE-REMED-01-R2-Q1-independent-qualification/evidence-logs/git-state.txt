0ebc38cb7fc677edd0b1923651bffcb54fd5a27e jenol <jenolaszlo-sketch@users.noreply.github.com> jenol <jenolaszlo-sketch@users.noreply.github.com> Fix listener shutdown so an accepted connection is never abandoned The accept loop awaited a cancellable accept while shutdown cancelled the token and closed the listening socket underneath it. On Windows a pending AcceptEx whose completion is never retrieved leaves the accepted socket ESTABLISHED with no FIN and no RST, so a peer that completed the TCP handshake but had not yet sent a protocol byte never observed closure (B5B-CI-RACE-REMED-01-R2). The WIP socket registry could not help because nothing had been accepted by the application yet.  - Run the accept without a cancellation token and quiesce it with a bound   loopback sentinel before closing the listening socket; drain and dispose   anything that raced with shutdown so acceptance can never be missed and no   accept is left outstanding at close. - Replace the task/socket dictionaries with one connection registry that   owns the socket, registers it before its pipeline can run, and retires it   only after termination is established. - Reserve a share of the shutdown budget for forced socket termination and   expose incomplete termination through BoltShutdownOutcome. - Make StopAsync idempotent under concurrency, keep caller cancellation from   abandoning the shutdown, and stop counting shutdown cancellation as a TLS   authentication failure.  Adds ListenerShutdownLifecycleTests covering repeated negotiation shutdown, TLS authentication cancellation, concurrent accepts during shutdown, forced termination, observable incomplete shutdown, caller cancellation, repeated and concurrent stop, and graceful shutdown preservation.
