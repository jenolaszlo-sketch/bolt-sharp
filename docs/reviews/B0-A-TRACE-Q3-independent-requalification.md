## Findings

**TRACEQ2-F01 (original MAJOR), OPEN against full Q3 criteria.** The original implementation mapped broad socket and IO exceptions to CLOSED or CLEAN_EOF. R2 narrows acquisition, negotiation and first/additional framed-read catches using a six-code closure set and recursively recognizes IO-wrapped causes. The unchanged Q2 suite now passes all six previously failing assertions; its acquisition hook detects NetworkDown as ERROR. Q3 injected NetworkDown, NetworkUnreachable, NoBufferSpaceAvailable, TimedOut, AccessDenied, wrappers and unexpected IO at the first framed-read boundary: all yielded ERROR. The exact Q2-baseline source negative control yielded 7 failures / 8 passes in the 15 Q3 injected cases, detecting broad suppression. Producer R2's competing shutdown/injected-fault test also passes; it is not an independent Q3 race probe.

**Q3-F01 — closure exceptions reported as clean EOF.** `ObserveFirstMessageAsync` and the additional-message handler apply the same six socket codes without checking execution context and assign `CLEAN_EOF`. Q3 injects each as an IOException inner cause with an unsignaled token: ConnectionReset, ConnectionAborted, OperationAborted, NotConnected, Shutdown, and Disconnecting all yield CLEAN_EOF. In particular, an injected reset/abort is an exceptional termination, not a read returning zero; OperationAborted with no signaled cancellation is not established as local shutdown. The first-message trace preserves ErrorType, but its status says clean EOF; the additional-message path also assigns CLEAN_EOF. This contradicts this assignment's requirement that CLEAN_EOF mean genuine clean EOF and that closure codes be assessed in context. The six historical failure cases are fixed; this is a distinct remaining classification counterexample, not a claim that a real outage was reproduced. Reassess how reset/abort and unverified local-abort causes should be represented within the existing taxonomy and test both first and additional reads. Severity: MINOR trace-semantics defect; it prevents the requested closure determination. The accept loop and DisposeAsync also broadly suppress SocketException in shutdown paths; no Q3 injection established a reachable loss there, so it is a coverage concern rather than a second demonstrated finding.

The real loopback abort attempt used zero-linger close. Its read returned zero, status CLEAN_EOF, and null ErrorType; it did **not** demonstrate a delivered socket-reset exception. An initial assertion expecting IOException failed (15 passed, 1 failed); retained `q3-final` TRX/output. The corrected observation test records the actual EOF and passes; it does not prove network reset classification. Genuine injected zero-byte EOF is separately CLEAN_EOF. Wrapped non-IO exception chains, acquisition and negotiation beyond retained Q2 probes, and every race interleaving were not independently exhausted.

**TRACEQ2-F02 (original MINOR), INCONCLUSIVE in full; local shutdown behavior supported.** Original post-handshake ODE became ERROR. R2 maps direct or IO-wrapped ODE to CANCELLED for first and additional observations. The documented remediation contract explicitly says CANCELLED includes local operation shutdown/disposal, not only a signaled token; for an actual listener-owned stream disposed during shutdown that label is consistent and distinct from CLEAN_EOF. Q2 Q21 and Q24 pass, as do R1 shutdown tests. An external peer close does not itself dispose the local TcpClient; the attempted real peer abort here returned EOF. However, Q3 injection of an ODE naming an unrelated resource with no token signaled also yields CANCELLED: the predicate examines exception type and IO wrappers, not object identity or shutdown state. This demonstrates the classifier cannot distinguish causes, but not that an unrelated disposed resource is reachable in the current listener-owned stream path. Thus no claim of an actual concealed defect or categorical closure for all possible disposal origins. Establish the reachable ownership assumptions or distinguish unexpected origins before closing without qualification; CLOSED could describe connection closure at the outer boundary but is not an available first-message status, and a new taxonomy is not proposed.

TRACEQ1-F01 remains closed for the original escaping endpoint/handler prologue defect: retained Q2 lifecycle 26/26 and R1 shutdown 10/10 pass, including bounded joins. These runs do not prove all schedules. TRACEQ1-F02 remains the previously observed defensive/unreachable capture-truncation behavior, not a new regression.
